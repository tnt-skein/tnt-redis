# tnt-redis

Клиент Redis для Tarantool: свой RESP2 поверх встроенного неблокирующего
сокета. Соединения живут в пуле, срок один на вызов, отказ — пара
`nil, err` с родом по коду ошибки Redis, а команды подряд уходят одной
записью.

```lua
local redis = require('tnt.redis')

local client = redis.new({ host = 'cache', password = secret, pool = { size = 4 } })

client:command({ 'SET', 'user:7', 'Анна', 'EX', 60 })
local name, err = client:command({ 'GET', 'user:7' })        -- промах — nil без err
local replies, err = client:pipeline({ { 'INCR', 'hits' }, { 'EXPIRE', 'hits', 60 } })
```

Зависимости: `tnt-must` (проверки аргументов), `tnt-log` (журнал),
`tnt-pool` (соединения), `tnt-retry` (повторы), `tnt-external` (подмена
сети и шифрования в проверках), `tnt-storage` (срок, отказ с родом
и запись значения строкой) и `tnt-tls` (шифрование).

## Зачем

Готового клиента Redis у Tarantool нет ни в ядре, ни среди официальных
роков, а блокирующая библиотека на C остановила бы узел целиком. Пакет
говорит протоколом сам, на файберах, и закрывает места, где голый
протокол подводит молча:

- **Аргумент уходит точной строкой**: `1e15` — цифрами, а не `1e+15`,
  которое `INCRBY` отвергает; `int64` — без `LL`; `decimal`, `uuid`
  и время — текстом. Логика и пустое — исключение, а не догадка,
  `'0'` это или `''`.
- **Промах — `nil`, пустое в массиве — `box.NULL`**: `MGET` с промахом
  посередине не теряет хвост.
- **Отказ — пара `nil, err` с родом** (`unreachable`, `denied`, `busy`,
  `timeout`, `broken`, `rejected`, `overflow`, `closed`), признаком
  отправки и приговором повтору — и ошибка внутри массива из `EVAL` тоже.
- **Повтор после отправки — только с `idempotent = true`**: `INCR`,
  оборванный после записи, не посчитается дважды.
- **Соединение в пуле не портится**: `SELECT`, `AUTH`, `MULTI`,
  `SUBSCRIBE` и прочие команды, после которых следующий взявший получил бы
  чужое соединение, — исключение; ответ дочитывается до конца и с ошибкой
  внутри; предел байтов бережёт память узла.

## Установка

```sh
tt rocks install tnt-redis --server=https://tnt-skein.github.io/rocks
```

Или из исходников:

```sh
git clone https://github.com/tnt-skein/tnt-redis.git
cd tnt-redis && tt rocks make
```

## Как пользоваться

| Вызов | Что делает |
|---|---|
| `redis.new(opts)` | заводит драйвер, соединений не открывает; негодная или незнакомая настройка — исключение |
| `client:command(args, opts)` | одна команда; ответ значением Lua, промах — `nil`; `timeout`, `idempotent` |
| `client:pipeline(commands, opts)` | команды одной записью, ответы списком по порядку; ошибка любой — отказ вызова |
| `client:stats()` | показатели пула без учётных данных |
| `client:close()` | закрывает пул: свободные соединения сразу, занятые — когда вернут |

Настройки драйвера: `host`, `port` (6379), `username` и `password`
(учётке ACL нужен пароль), `db` (0), `tls` (`true` либо
`{ verify, ca_file, ca_path, sni, cert_file, key_file }`; сертификат
клиента — серверу с `tls-auth-clients yes`; непринятый сертификат
сервера — `denied` сразу), `timeout` и `max_timeout` (5 и 60 с),
`max_bytes` (16 МБ), `pool` и `retry` (как у `tnt-pool` и `tnt-retry`),
`name`.

```lua
local value, err = client:command({ 'LPUSH', 'user:7', 'x' })

if err ~= nil and err.kind == 'rejected' and err.server_code == 'WRONGTYPE' then
    -- ключ хранит не список
end

local hits, err = client:command({ 'GET', 'hits' }, { timeout = 0.5, idempotent = true })
```

## Проверки

```sh
make deps          # luatest, luacheck, luacov с cluacov и зависимости пакета в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
make redis-up      # Redis 7.4 в докере для живых проверок; make redis-down — погасить
```

Покрытие строк — 100 %, убитых мутантов — 100 % (83 проверки,
375 мутантов в четырёх модулях). Протокол проверяется без сети
и двойником сервера на настоящем сокете, а тринадцать живых проверок идут
против Redis 7.4 стенда — и против сервера, требующего сертификат
клиента; без поднятого сервера они пропускаются.
